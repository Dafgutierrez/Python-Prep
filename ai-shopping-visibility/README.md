# AI Shopping Visibility — prototype

A working prototype of the "share of voice across AI shopping engines" pipeline
discussed alongside Azoma-style tools (ChatGPT, Gemini, Claude, Perplexity —
and explicitly **not** Alexa for Shopping / Amazon Rufus; see below). Demo
category: wireless earbuds, tracked brand: `Soundpeats` (both placeholders,
swap for your real category/brand in `data/catalog.json`).

Dashboard (mock data, generated by this pipeline): published as a Claude
Artifact when this was built — regenerate with `python3 run_demo.py` and
re-embed into `dashboard.html` to refresh it (see "Regenerating the dashboard"
below).

## What's actually real here vs. simulated

| Piece | Status |
|---|---|
| Prompt bank (seed questions + template expansion) | Real. Seeds are grounded in shopping-question patterns observed via web research (tech-review consensus coverage); see `data/seed_questions.json` for source notes. |
| Engine query layer (`src/engines.py`) | Real interface, **mock responses**. No API keys configured — see "Going live" below. |
| Classifier (`src/classifier.py`) | Real, alias-based string matching against `data/catalog.json`. |
| Storage + share-of-voice math (`src/storage.py`) | Real SQLite pipeline; SOV = a product/brand's mentions ÷ total mentions in that run. |
| Dashboard (`dashboard.html`) | Real UI, rendering whatever `data/dashboard_export_trimmed.json` contains — currently mock data. |

## Why Alexa for Shopping / Amazon Rufus isn't in here

Covered in detail in conversation, summarized for the record: Amazon has no
public API for Rufus/Alexa+ shopping answers. The only way to query it
programmatically is automating the consumer Alexa app or a physical device,
which almost certainly violates Amazon's Conditions of Use / Alexa Terms and
risks account and device bans, on top of being fragile (breaks on every UI
change). This repo treats that channel as **"buy the data from a vendor"**
(e.g. Azoma, Profitero, Ecomtent) rather than something to build in-house.
`src/engines.py` has a comment to this effect at the top so the reasoning
doesn't get lost if this code is picked up again later.

## Project layout

```
ai-shopping-visibility/
  data/
    catalog.json                    tracked brand + competitor products/ASINs (mock ASINs)
    seed_questions.json             real-shopper-language seed prompts + source notes
    prompt_bank.json                generated by src/prompt_bank.py
    visibility.db                   SQLite db, generated by run_demo.py / src/pipeline.py
    dashboard_export.json           full export, generated by run_demo.py
    dashboard_export_trimmed.json   trimmed payload embedded into dashboard.html
  src/
    prompt_bank.py                  seed + template-expansion prompt bank builder
    engines.py                      per-engine query abstraction (mock/live seam)
    classifier.py                   brand/ASIN mention extraction
    storage.py                      SQLite schema + share-of-voice queries
    pipeline.py                     one end-to-end run (prompt bank -> engines -> classifier -> storage)
  run_demo.py                       simulates 8 weekly runs, exports dashboard data
  dashboard.html                    the dashboard UI (data embedded as a JS const)
```

## Running it

```bash
cd ai-shopping-visibility
python3 run_demo.py          # simulates 8 weekly runs with mock engines, writes data/dashboard_export*.json
python3 -m src.pipeline       # or: run a single ad-hoc pipeline pass, prints SOV to stdout
```

No dependencies beyond the Python 3 standard library.

## Regenerating the dashboard

`dashboard.html` has the dashboard data embedded as a literal JS object (not
fetched at runtime — artifacts/static pages can't reliably read local files).
After changing `data/catalog.json`, `data/seed_questions.json`, or re-running
the pipeline, re-embed:

```bash
python3 run_demo.py
python3 - <<'EOF'
import json
d = json.load(open("data/dashboard_export.json"))
trimmed = {
    "generated_at": d["generated_at"], "category": d["category"], "tracked_brand": d["tracked_brand"],
    "trend": [{"week_start": w["week_start"], "by_brand": {b["brand"]: b["sov_pct"] for b in w["by_brand"]}} for w in d["weekly"]],
    "latest_week_start": d["latest"]["week_start"], "by_brand": d["latest"]["by_brand"],
    "by_asin": d["latest"]["by_asin"], "by_brand_and_engine": d["latest"]["by_brand_and_engine"],
    "prompts": d["latest"]["prompts"],
}
json.dump(trimmed, open("data/dashboard_export_trimmed.json", "w"))
EOF
```

Then replace the `const DATA = {...};` block in `dashboard.html` with the new
contents of `data/dashboard_export_trimmed.json`.

## Going live (swapping mock engines for real APIs)

Each engine in `src/engines.py` checks an env var and falls back to a mock
responder if it's unset:

| Engine | Env var | SDK to wire up in `_call_live` |
|---|---|---|
| ChatGPT | `OPENAI_API_KEY` | official `openai` SDK, chat completions / responses API |
| Gemini | `GOOGLE_API_KEY` | official `google-generativeai` SDK |
| Claude | `ANTHROPIC_API_KEY` | official `anthropic` SDK |
| Perplexity | `PERPLEXITY_API_KEY` | Perplexity's chat completions API |

Set the env var, implement `_call_live`, and `Engine.answer()` picks it up
automatically — no other code changes needed. **Never hardcode a key in this
repo**; use environment variables or a secrets manager.

## Compliance notes for extending the prompt bank

If you want to add real Reddit-sourced phrasing to `data/seed_questions.json`
later (right now it's grounded in tech-review consensus coverage, not literal
Reddit post text — Reddit blocks automated fetching, which is what surfaced
this in the first place):

- **Reddit**: use the official Reddit API via an approved app + `PRAW`
  (or the raw API) under Reddit's Data API terms, not scraping the HTML.
  Respect rate limits and Reddit's usage policy for the data's intended use
  (research/analytics is generally fine; redistributing raw content is not).
- **Google** ("People Also Ask", autocomplete, etc.): use Google's official
  Custom Search JSON API or a licensed SERP-data provider, not raw HTML
  scraping of search results pages, which violates Google's Terms of Service.
- **Alexa/Rufus**: see above — don't automate the consumer surface. Buy this
  data if you need it.

## Known simplifications (would need work before this is production-grade)

- The classifier is exact alias string-matching. Real engine answers are
  messier (paraphrased brand names, no numbered lists) — the natural upgrade
  is an LLM-based extraction call; `extract_mentions()` in `classifier.py` is
  the single seam to swap without touching storage or the dashboard.
- ASINs in `data/catalog.json` are placeholders (`B0EXAMPLE#`). In production
  this file is generated from your real Amazon catalog feed.
- No scheduler is wired up. `src/pipeline.run_pipeline()` is the function a
  cron job / Airflow DAG / etc. would call on a recurring cadence.
- No retries/backoff/rate-limiting on the (currently unimplemented) live
  engine calls — add this before pointing real API keys at it.
